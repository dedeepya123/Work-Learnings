# Gemma4 Attention — Concept → Implementation

## Core flow

hidden_states
→ Q/K/V projections
→ Q/K/V normalization
→ RoPE on Q/K
→ KV cache / KV sharing
→ QKᵀ
→ causal/sliding mask
→ softmax
→ attention × V
→ reshape
→ output projection

## Tensor shapes

Input:
[B, Q, hidden_size]

Q:
[B, num_attention_heads, Q, head_dim]

K/V:
[B, num_key_value_heads, KV, head_dim]

Attention scores:
[B, num_attention_heads, Q, KV]

Attention mask:
[B, 1, Q, KV]

Output:
[B, Q, hidden_size]

## RoPE

x' = x * cos(theta) + rotate_half(x) * sin(theta)

rotate_half:
[a,b,c,d] → [-c,-d,a,b]

RoPE is applied to Q and K, not V.

RoPE answers:
"What position does this Q/K represent?"

Mask controls visibility.
RoPE provides positional information.
KV cache provides temporal reuse.

## KV cache vs KV sharing

KV cache:
same layer across generation steps/time.

KV sharing:
different layers reuse K/V.

They solve different problems.

## Gemma4 layer_type

layer_type influences:
- RoPE parameters
- attention mask
- cache layer type
- attention behavior
- KV sharing behavior

full_attention:
- full causal visibility
- full KV history

sliding_attention:
- bounded local visibility
- sliding-window cache

## Important distinction

RoPE ≠ causal mask ≠ KV cache

RoPE → positional information
Mask → allowed attention connections
KV cache → reuse previously computed K/V
