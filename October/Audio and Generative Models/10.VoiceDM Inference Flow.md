# 09 - VoiceDM Inference Flow

## Why Start Here?

Before studying internal architecture details, it is useful to understand how a user interacts with VoiceDM and how data flows through the system.

The entry point of the model is a simple command:

```bash
python3 example.py \
  --input_text="Hello from VoiceDM!" \
  --output_wav=output.wav
```

Conceptually:

```text
Input Text
      ↓
VoiceDM
      ↓
Waveform Audio
      ↓
output.wav
```

However, several intermediate processing stages occur between these two points.

---

## High-Level Pipeline

```text
Input Text
      ↓
Tokenization
      ↓
VoiceDM Encoder
      ↓
Conditioning Representation
      ↓
VoiceDM Decoder (DiT)
      ↓
Audio Features [B, T, 96]
      ↓
SoundStream Decoder
      ↓
STFT Frames
      ↓
IRFFT + Overlap Add
      ↓
Waveform
      ↓
output.wav
```

---

## Step 1: Parse User Input

The example script accepts:

```bash
python3 example.py \
  --input_text="Hello from VoiceDM!" \
  --output_wav=output.wav
```

Optional:

```bash
--prompt_wav_path=speaker.wav
```

Required:

```text
input_text
output_wav
```

Optional:

```text
speaker prompt audio
```

---

## Step 2: Speaker Prompt Processing

If a speaker prompt is provided:

```python
--prompt_wav_path=speaker.wav
```

the script:

```text
Load WAV
 ↓
Convert To Mono
 ↓
Resample To 24 kHz
 ↓
SoundStream Encoder
 ↓
Speaker Embeddings
```

Conceptually:

```text
Reference Speaker Audio
            ↓
SoundStream Encoder
            ↓
Speaker Features
            ↓
Voice Conditioning
```

Purpose:

```text
Preserve speaker identity.
```

This allows generated speech to sound similar to the reference speaker.

---

## Step 3: Speaker Prompt Tensor

The encoded speaker representation is converted into:

```python
[1, 83, 96]
```

If the encoded prompt contains fewer than:

```text
83 frames
```

it is padded.

If it contains more than:

```text
83 frames
```

it is truncated.

Final shape:

```python
speaker_prompt_array
=
[1, 83, 96]
```

---

## Step 4: Text Processing

The input sentence:

```text
"Hello from VoiceDM!"
```

is tokenized:

```python
text_tokens_torch =
    voicedm_inference.text_tokenizer(sentence)
```

Conceptually:

```text
Raw Text
    ↓
Tokenizer
    ↓
Token IDs
```

Similar to:

```text
LLMs
```

which convert text into token IDs before inference.

---

## Step 5: Text Padding

VoiceDM expects a fixed-size input tensor.

The token sequence is padded or truncated to:

```python
256 tokens
```

Result:

```python
tokenized_text_array
=
[1, 256]
```

Additionally:

```python
tokenized_text_size
```

stores the real text length before padding.

---

## Step 6: Audio Context

Current inference uses:

```python
audio_context_array =
    np.zeros((1, 100, 96))
```

and

```python
audio_context_size =
    np.zeros((1,))
```

Conceptually:

```text
No Previous Audio Context
```

The model therefore generates speech from scratch.

In future scenarios:

```text
Previous Audio
```

could be encoded and supplied as context.

---

## Step 7: VoiceDM Encoder

Inputs:

```python
tokenized_text_array
speaker_prompt_array
audio_context_array
```

Flow:

```text
TextEncoder
      ↓
SpeakerEncoder
      ↓
AudioContextEncoder
      ↓
MetaEncoder
      ↓
Conditioning Tensor
```

Output:

```python
cond
cond_paddings
```

Purpose:

```text
Create a single representation describing:

- What to say
- Who should say it
- What context to follow
```

---

## Step 8: VoiceDM Decoder (DiT)

The conditioning tensor is passed into the diffusion decoder.

Conceptually:

```text
Noise
     +
Conditioning
     ↓
8-Step Diffusion
     ↓
Audio Features
```

Output:

```python
[B, T, 96]
```

These features are not waveform audio.

They are learned audio representations.

---

## Step 9: Early Decode Optimization

VoiceDM first decodes only:

```python
15 frames
```

using:

```python
soundstream_early_decode(...)
```

Conceptually:

```text
Audio Features
        ↓
Decode Preview
        ↓
Check For Silence
```

Purpose:

```text
Avoid expensive full decoding
when the output already contains long silence.
```

---

## Step 10: Full Decode

If speech continues:

```python
soundstream_full_decode(...)
```

is executed.

Flow:

```text
Audio Features [B,T,96]
         ↓
SoundStream Decoder
         ↓
STFT Frames
```

This uses the same SoundStream decoder model.

The only difference is that the entire feature sequence is decoded.

---

## Step 11: Waveform Reconstruction

Inside SoundStream post-processing:

```text
STFT Frames
      ↓
IRFFT
      ↓
Window Compensation
      ↓
Overlap Add
      ↓
Waveform
```

Output:

```python
[B, NumSamples]
```

This is actual playable audio.

---

## Step 12: Output Processing

Generated waveform segments are:

```text
Concatenated
 ↓
Normalized
 ↓
Written To Disk
```

using:

```python
wavfile.write(...)
```

Result:

```text
output.wav
```

---

## End-to-End Tensor Journey

```text
Input Text
      ↓
Tokenizer
      ↓
Token IDs [1,256]

Speaker WAV
      ↓
SoundStream Encoder
      ↓
Speaker Features [1,83,96]

Audio Context
      ↓
Context Features [1,100,96]

VoiceDM Encoder
      ↓
Conditioning Tensor

Noise
      ↓
VoiceDM Decoder (DiT)
      ↓
Audio Features [B,T,96]

SoundStream Decoder
      ↓
STFT Frames

IRFFT + Overlap Add
      ↓
Waveform

output.wav
```

---

## Key Takeaways

- VoiceDM inference begins with text and optional speaker audio.
- Text is tokenized and padded to a fixed length.
- Speaker audio is encoded using SoundStream.
- VoiceDMEncoder creates a conditioning representation.
- VoiceDMDecoder uses diffusion to generate audio features.
- SoundStreamDecoder converts audio features into STFT frames.
- IRFFT and overlap-add reconstruct waveform audio.
- Early decoding is used as a latency optimization before full decoding.
- The final output is stored as a `.wav` file.
