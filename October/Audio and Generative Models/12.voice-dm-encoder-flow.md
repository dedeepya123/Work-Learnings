# 10 - VoiceDM Encoder Flow

## Why This Layer Exists

Before audio generation can begin, VoiceDM must construct a conditioning representation.

The top-level encoder entry point is:

```python
voicedm_encode(...)
```

This function performs:

```text
Input Validation
      ↓
Preprocessing
      ↓
Padding Generation
      ↓
Model Loading
      ↓
VoiceDMEncoder Forward Pass
```

Think of it as the orchestration layer around the actual neural network.

---

## Inputs

VoiceDMEncoder receives three types of information.

### Text

```python
tokenized_text_array
```

Shape:

```python
[B, 256]
```

Purpose:

```text
What should be spoken?
```

Real length:

```python
tokenized_text_size
```

Shape:

```python
[B]
```

---

### Speaker Prompt

```python
speaker_prompt_array
```

Shape:

```python
[B, 83, 96]
```

Purpose:

```text
Who should speak?
```

Real length:

```python
speaker_prompt_size
```

Shape:

```python
[B]
```

---

### Audio Context

```python
audio_context_array
```

Shape:

```python
[B, 100, 96]
```

Purpose:

```text
What previous audio context should be followed?
```

Real length:

```python
audio_context_size
```

Shape:

```python
[B]
```

---

## Step 1 - Input Validation

The encoder first validates expected tensor shapes.

```python
assert tokenized_text_array.shape[1] == 256
assert speaker_prompt_array.shape[1] == 83
assert audio_context_array.shape[1] == 100
```

Expected inputs:

```python
Text            -> [B, 256]
Speaker Prompt  -> [B, 83, 96]
Audio Context   -> [B, 100, 96]
```

These fixed sizes simplify deployment and model execution.

---

## Step 2 - Text Preprocessing

VoiceDM does not directly consume raw token IDs.

Instead:

```python
preprocess_text(...)
```

is called.

Conceptually:

```text
Raw Tokens
      ↓
Offset Tokens
      ↓
Add EOS
      ↓
Generate Padding Mask
```

Outputs:

```python
t_text
text_paddings
```

Purpose:

```text
Create transformer-ready text inputs.
```

---

## Step 3 - Speaker Padding Generation

Next:

```python
size_to_paddings(...)
```

creates speaker masks.

Input:

```python
speaker_prompt_size
```

Output:

```python
speaker_paddings
```

Shape:

```python
[B, 83]
```

Conceptually:

```text
Real Frames
      ↓
Padding Mask
```

The model can now distinguish:

```text
Valid Speaker Frames
```

from

```text
Padded Frames
```

---

## Step 4 - Audio Context Padding Generation

The same process is applied to audio context.

Input:

```python
audio_context_size
```

Output:

```python
audio_ctx_paddings
```

Shape:

```python
[B, 100]
```

Conceptually:

```text
Audio Context Length
           ↓
Audio Context Mask
```

---

## Step 5 - Model Instantiation

The actual encoder model is created.

```python
model = _instantiate_voicedm_encoder(...)
```

Possible options:

```python
apply_fake_quant
use_craft
craft_int_precision
checkpoint_path
```

---

### Quantization Hooks

Several parameters already exist for quantization workflows.

```python
apply_fake_quant
```

Used for fake quantization experiments.

---

```python
use_craft
```

Enables CRAFT activation clipping.

---

```python
craft_int_precision
```

Controls:

```text
INT8
INT16
```

style activation quantization.

---

This is important because our AIMET work will likely interact with similar portions of the model lifecycle.

---

## Step 6 - VoiceDMEncoder Forward Pass

Once preprocessing is complete:

```python
model(...)
```

is called.

Inputs:

```python
tokenized_text
text_paddings

speaker_prompt
speaker_paddings

audio_context
audio_ctx_paddings
```

Conceptually:

```text
Text Features
      +
Speaker Features
      +
Audio Context Features
      ↓
VoiceDMEncoder
```

---

## Outputs

The encoder returns:

```python
cond
cond_paddings
```

---

### cond

Shape:

```python
[B, cond_len, model_dims]
```

Purpose:

```text
Unified conditioning representation
```

containing information about:

```text
What to say
Who should say it
What context to follow
```

---

### cond_paddings

Shape:

```python
[B, cond_len]
```

Purpose:

```text
Mask identifying valid conditioning positions.
```

---

## High-Level Flow

```text
Text Tokens [B,256]
          +
Speaker Prompt [B,83,96]
          +
Audio Context [B,100,96]
                    ↓

            Preprocessing
                    ↓

            Padding Masks
                    ↓

             VoiceDMEncoder
                    ↓

                 cond
                    ↓

           Conditioning Tensor
```

---

## Mental Model

Think of `voicedm_encode()` as a preparation layer.

Its responsibilities are:

```text
Validate Inputs
        ↓
Create Masks
        ↓
Load Model
        ↓
Run Encoder
```

The actual neural network begins inside:

```text
VoiceDMEncoder
```

which is the next component we will study.

---

## Key Takeaways

- `voicedm_encode()` is an orchestration wrapper around the actual encoder model.
- Text preprocessing creates transformer-ready token inputs.
- Speaker and audio-context lengths are converted into padding masks.
- The wrapper handles model instantiation and quantization-related options.
- The final output is a conditioning representation (`cond`) used by the diffusion decoder.
- No audio generation happens in the encoder.
