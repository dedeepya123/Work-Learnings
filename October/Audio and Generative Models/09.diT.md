# 08 - DiT (Diffusion Transformer): Where Does the Transformer Fit?

## Recap

In the previous lesson, we learned the core idea behind diffusion.

Instead of generating an output directly, diffusion works by repeatedly improving a noisy representation.

Conceptually:

```text
Noise
 ↓
Denoise
 ↓
Denoise
 ↓
Denoise
 ↓
Final Output
```

For modern audio systems, the output is often:

```text
Audio Latents
```

or

```text
Audio Features
```

rather than waveform audio itself.

This naturally leads to an important question:

> What neural network actually performs the denoising?

Something has to look at the noisy representation and predict how to make it cleaner.

Historically, the answer was:

```text
U-Net
```

In modern systems, the answer is increasingly:

```text
Transformer
```

This architecture is called:

```text
DiT
=
Diffusion Transformer
```

---

## The Job of the Denoising Network

Let's forget audio for a moment.

Imagine we have:

```text
Noisy Data
```

and we want:

```text
Cleaner Data
```

The diffusion process repeatedly asks:

```text
Current Representation
         ↓
Neural Network
         ↓
Improved Representation
```

The neural network's job is simple:

> Look at the current noisy state and predict how to move closer to the real data.

Every denoising step uses the same model.

---

## Historical Choice: U-Net

In early diffusion systems, researchers often used:

```text
U-Net
```

especially for images.

Conceptually:

```text
Noisy Image
 ↓
U-Net
 ↓
Predicted Noise
```

This worked extremely well.

As diffusion became popular, U-Nets became the standard architecture.

---

## Then Transformers Took Over

Researchers noticed something important.

Transformers were succeeding everywhere:

```text
NLP
Vision
Multimodal Systems
```

because they are extremely good at modeling relationships across large contexts.

This led to a natural question:

> Can a Transformer replace the U-Net inside diffusion?

The answer was:

```text
Yes
```

and this idea became:

```text
Diffusion Transformer
```

or

```text
DiT
```

---

## What Is DiT?

At a very high level:

```text
Diffusion
+
Transformer
=
DiT
```

The diffusion process remains exactly the same.

The only thing that changes is:

```text
Which neural network performs denoising?
```

Instead of:

```text
U-Net
```

we use:

```text
Transformer
```

---

## Don't Overcomplicate It

Many people hear:

```text
Diffusion Transformer
```

and assume it is a completely new concept.

It isn't.

Think of it this way:

### Original Diffusion

```text
Noise
 ↓
U-Net
 ↓
Cleaner Output
```

### DiT

```text
Noise
 ↓
Transformer
 ↓
Cleaner Output
```

The diffusion process has not changed.

Only the denoising network changed.

---

## Connecting This to What We Already Know

You already know Transformers.

A Transformer accepts:

```text
Sequence
```

and produces:

```text
Better Sequence Representation
```

For example:

```text
Tokens
 ↓
Transformer
 ↓
Hidden States
```

DiT uses the same idea.

Instead of:

```text
Text Tokens
```

the Transformer receives:

```text
Noisy Audio Features
```

or

```text
Noisy Audio Latents
```

and predicts how to denoise them.

---

## A High-Level View

Consider an audio latent tensor:

```python
[B, 100, 96]
```

The diffusion process may produce:

```python
Noisy Latents
```

with the same shape.

DiT receives:

```python
[B, 100, 96]
```

and outputs:

```python
[B, 100, 96]
```

representing a cleaner version or a prediction of the noise.

Conceptually:

```text
Noisy Audio Features
          ↓
         DiT
          ↓
Cleaner Audio Features
```

---

## Why Are Transformers Attractive?

You already know one major reason.

Transformers are very good at modeling long-range relationships.

Consider speech.

Speech contains dependencies across time:

```text
Words
Phonemes
Prosody
Rhythm
Speaker Characteristics
```

A transformer can attend across the entire sequence.

Conceptually:

```text
Position 1
 ↘
Position 40
 ↘
Position 90
```

This ability often helps generate more coherent outputs.

---

## The Additional Inputs

Remember something important.

DiT does not receive only noisy features.

It also needs information about:

```text
Current Diffusion Step
```

because the behavior needed at:

```text
Step 5
```

is different from:

```text
Step 500
```

So conceptually:

```text
Noisy Audio Features
           +
     Timestep
           ↓
          DiT
           ↓
 Denoising Prediction
```

---

## Conditioning

Most generative audio models also need context.

For example:

```text
Input Text
```

must influence the generated speech.

Otherwise the model would generate random sounds.

This information is called:

```text
Conditioning
```

Conceptually:

```text
Text
 ↓
Conditioning Features
```

which are supplied to the diffusion process.

Now the picture becomes:

```text
Noisy Audio Features
         +
Text Conditioning
         +
Diffusion Step
         ↓
        DiT
         ↓
Denoising Prediction
```

---

## This Should Feel Familiar

Think about an LLM.

An LLM performs:

```text
Input Tokens
 ↓
Transformer
 ↓
Output Representation
```

DiT performs:

```text
Noisy Audio Features
 ↓
Transformer
 ↓
Cleaner Audio Features
```

The transformer architecture is the same idea.

The task is different.

## Connecting This To VoiceDM

Now we can start explaining VoiceDM more confidently.

A simplified view is:

```text
Text
 ↓
VoiceDM Encoder
 ↓
Conditioning Features
 ↓
DiT
 ↓
Audio Features
 ↓
SoundStream Decoder
 ↓
Waveform Reconstruction
 ↓

```

Notice the responsibility of each component.

### VoiceDM Encoder

Produces:

```text

```

### DiT

Produces:

```text
Audio Features
```

---

### SoundStream Decoder

Produces:

```text

```

```text
Waveform Audio
```

## What Does DiT Actually Output?

This is one of the most important questions to ask when reading audio papers.

The answer is usually NOT:

```text
Audio Waveform
```

Instead it is often:

```text
Audio Latents
```

or

```text
Audio Features
```

These representations are subsequently decoded.

The decoder remains responsible for producing actual audio.

## Key Takeaways

- Diffusion requires a neural network to perform denoising.
- Historically this network was often a U-Net.
- DiT replaces the U-Net with a Transformer.
- The diffusion process itself remains unchanged.
- DiT operates on noisy representations and progressively improves them.
- DiT receives noisy features, timestep information, and conditioning signals.
- In audio systems, DiT often generates audio latents or audio features rather than waveforms.
- Transformers are attractive because they model long-range dependencies effectively.

---

## Interview Takeaway

DiT (Diffusion Transformer) is a diffusion model that uses a Transformer as the denoising network. During generation, noisy audio representations are repeatedly refined through denoising steps until meaningful audio features emerge. In modern speech systems such as VoiceDM, DiT is typically responsible for generating audio latents or audio features, which are later converted into waveform audio by a decoder such as SoundStream.
