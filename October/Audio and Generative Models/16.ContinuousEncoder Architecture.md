# ContinuousEncoder Architecture

## Purpose

Unlike the TextEncoder, which processes discrete token IDs, the ContinuousEncoder processes continuous feature vectors.

It is used by:

```text
SpeakerEncoder

AudioContextEncoder
```

within VoiceDM.

Conceptually:

```text
Continuous Features
        ↓
Linear Projection
        ↓
Add CLS Tokens
        ↓
Transformer Encoder
        ↓
Extract CLS Representations
        ↓
Output Features
```

The purpose is to summarize an entire sequence of audio features into a compact conditioning representation.

---

## Where It Is Used

### Speaker Encoder

Input:

```python
[B,83,96]
```

Represents:

```text
Reference Speaker Audio Features
```

Output:

```text
Speaker Representation
```

---

### Audio Context Encoder

Input:

```python
[B,100,96]
```

Represents:

```text
Previous Audio Context Features
```

Output:

```text
Audio Context Representation
```

---

## High-Level Architecture

```text
Input Features
       ↓

Linear Projection
       ↓

Prepend CLS Tokens
       ↓

LayerNorm
       ↓

Transformer Encoder
       ↓

LayerNorm
       ↓

Extract CLS Tokens
       ↓

       ↓

Output Representation
```

# Step 2 - CLS Tokens

The model contains learnable CLS tokens.

```python
self.cls_tokens
```

Shape:

```python
[num_cls_tokens, model_dims]
```

Example:

```python
[32,256]
```

---

## Why CLS Tokens?

Think about BERT.

```text
[CLS]
 sentence
```

The CLS token gathers information from the entire sequence.

VoiceDM extends this idea.

Instead of:

```text
1 CLS Token
```

it uses:

```text
32 CLS Tokens
```

---

These tokens act as learned summary vectors.

During attention they interact with every feature frame.

Conceptually:

```text
CLS Tokens
      ↕
Audio Features
```

Over time they collect useful information about the entire sequence.

---

# Step 4 - LayerNorm

After concatenation:

```python

```

is applied.

```text

```

---

# Step 5 - Padding Mask Adjustment

The transformer uses masks.

Original mask:

```python
[B,1,1,S]
```

covers only the audio features.

---

After adding CLS tokens:

```python
CLS positions
```

must never be masked.

So:

```python
cls_mask =
    zeros(...)
```

is created.

Then:

```python
mask =
    [cls_mask | original_mask]
```

is concatenated.

---

Conceptually:

```text
CLS Tokens
   ↓
Always Visible
```

---

Flow:

```text

 ↓
```

---

The CLS tokens attend to:

```text
Every Audio Feature
```

# Step 7 - Output LayerNorm


# Step 8 - Extract CLS Tokens

This is the most important operation.

```python
cls_out =
    h[:, :num_cls_tokens, :]
```

Only the CLS positions are kept.

---

```python

```

↓


# Step 9 - Optional Output Projection

Some ContinuousEncoders project to a new dimension.

```python
self.output_projection
```

---

Speaker Encoder Configuration:

```python
output_dims = 768
```

Audio Context Configuration:

```python
output_dims = 768
```

---

Shape:

```python
[B,32,256]
```

↓

```python
[B,32,768]
```

---

Why?

Because the MetaEncoder will later combine these representations with:

```python

```

Everything needs to live in the same feature space.

---


Audio Context Encoder:


---

# Why 32 CLS Tokens?

A single CLS token would force all information into one vector.

VoiceDM instead uses:

```text
32 Summary Tokens
```

allowing the model to preserve richer information.

Conceptually:

```text
Speaker Information
      ↓

32 Learned Summary Vectors

      ↓

MetaEncoder
```

This is similar to creating a compact set of learned "memory tokens".

# Mental Model

Think of ContinuousEncoder as:

```text
Audio Features
       ↓

Learnable Summary Tokens
       ↓

Transformer
       ↓

Extract Summaries
       ↓

Conditioning Features
```

Its job is to compress a variable-length sequence of audio features into a fixed set of learned representations.

---

# Key Takeaways

- ContinuousEncoder processes continuous audio feature inputs.
- SpeakerEncoder and AudioContextEncoder are both ContinuousEncoders.
- Input features are projected into transformer hidden space.
- 32 learnable CLS tokens are prepended.
- CLS tokens attend to the full sequence and collect information.
- Transformer layers contextualize both CLS tokens and input features.
- Only CLS outputs are retained.
- Outputs are projected into the shared 768-dimensional space.
- The final result becomes conditioning information for the MetaEncoder.
