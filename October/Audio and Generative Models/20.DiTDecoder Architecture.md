# DiTDecoder Architecture

## Purpose

DiTDecoder is the neural network responsible for denoising inside the diffusion process.

VoiceDMDecoder provides:

```text
Diffusion Schedule
Noise Sampling
DDPM Equations
```

DiTDecoder provides:

```text
The Intelligence
```

that learns how to transform noisy audio representations into valid audio features.

---

## Position Inside VoiceDM

```text
VoiceDMEncoder
        ↓

cond
cond_paddings

        ↓

VoiceDMDecoder
        ↓

DiTDecoder
        ↓

Predicted Velocity
        ↓

Diffusion Update
        ↓

Audio Features
```

---

# High-Level Mental Model

Think of DiT as:

```text
Diffusion
      +
Transformer
```

Exactly like how an LLM is:

```text
Tokens
      +
Transformer
```

The difference is the objective.

---

LLM:

```text
Predict Next Token
```

---

DiT:

```text
Predict Denoising Direction
```

---

# Inputs

DiT receives four inputs.

---

## Input 1 - Noisy Audio Features

```python
x
```

Shape:

```python
[B,T,96]
```

Example:

```python
[B,100,96]
```

Represents:

```text
Current Diffusion State
```

At early diffusion steps:

```text
Mostly Noise
```

At later diffusion steps:

```text
Mostly Audio Signal
```

---

## Input 2 - Timestep

```python
timestep
```

Shape:

```python
[B]
```

Example:

```python
[1.0]
```

or:

```python
[0.5]
```

---

Represents:

```text
Current Position
In The Diffusion Process
```

---

Without this input the model would not know:

```text
How Noisy
The Current Sample Is
```

---

## Input 3 - Conditioning Tensor

```python
cond
```

Shape:

```python
[B,320,768]
```

Represents:

```text
Speaker Information

Audio Context

Text Meaning
```

Generated previously by:

```text
MetaEncoder
```

---

## Input 4 - Conditioning Mask

```python
cond_paddings
```

Shape:

```python
[B,320]
```

Purpose:

```text
Identify valid conditioning positions.
```

# High-Level Architecture

```text
Noisy Features
       ↓

Input Projection
       ↓

Time Embedding
       ↓

DiT Block × 12
       ↓

Output Projection
       ↓

Predicted Velocity
```

---

# Step 1 - Input Projection

Input:

```python
[B,T,96]
```

Operation:

```python
Linear(
    96,
    768
)
```

---

Shape Transformation:

```python
[B,T,96]
```

↓

```python
[B,T,768]
```

---

Why?

Because transformer layers operate in:

```text
768-dimensional latent space.
```

---

Conceptually:

```text
Audio Features
      ↓
Transformer Hidden Space
```

---

# Step 2 - Time Embedding

Diffusion requires awareness of time.

The model creates:

```python
t_emb = self.time_emb(timestep)
```

using:

```python
SinusoidalTimeEmbedding
```

---

Conceptually:

```text
Current Diffusion Step
          ↓
Time Embedding
```

---

This is similar to positional embeddings in transformers.

---

Instead of:

```text
Position In Sentence
```

it represents:

```text
Position In Diffusion Process
```

---

# Why Time Embeddings Matter

Suppose we have:

```text
Step 1
```

Heavy noise.

---

and

```text
Step 8
```

Almost clean audio.

---

The model should behave differently in each case.

The time embedding provides this information.

---

# Step 3 - Cross Attention Mask

Conditioning contains padding.

Before entering DiT blocks:

```python
cross_mask
```

is created.

---

Shape:

```python
[B,1,1,cond_len]
```

Example:

```python
[B,1,1,320]
```

---

Purpose:

```text
Allow Attention To Active Tokens

Ignore Padding Tokens
```

---

This follows the same masking strategy used in transformer encoders.

---

# Step 4 - DiT Blocks

Core computation:

```python
for block in self.blocks:
    h = block(...)
```

---

VoiceDM uses:

```python
num_layers = 12
```

Therefore:

```text
DiT Block 1

 ↓

DiT Block 2

 ↓

DiT Block 3

 ...

 ↓

DiT Block 12
```

---

Each block receives:

```python
h
t_emb
cond
cross_mask
```

---

Meaning:

```text
Current Audio Representation

Current Diffusion Step

Conditioning Information
```

are available inside every DiT layer.

---

# What Happens Inside A DiT Block?

At a conceptual level:

```text
Self Attention
      ↓

Cross Attention
      ↓

Feed Forward Network
```

---

Self Attention:

```text
Audio Features
Attend To
Audio Features
```

---

Cross Attention:

```text
Audio Features
Attend To
Conditioning Tokens
```

---

Conditioning comes from:

```text
Text

Speaker

Context
```

---

This is how VoiceDM knows:

```text
What To Say

Who Should Speak

How To Speak
```

while denoising.

---

# Step 5 - Output Projection

After all 12 DiT blocks:

```python
self.output_projection(...)
```

is applied.

---

Operation:

```python
Linear(
    768,
    96
)
```

---

Shape:

```python
[B,T,768]
```

↓

```python
[B,T,96]
```

---

Result:

```text
Predicted Velocity Tensor
```

---

# Why "Velocity"?

VoiceDM uses:

```text
v-prediction
```

style diffusion.

The DiT is not directly predicting:

```text
Audio Features
```

Instead it predicts:

```text
How The Current Sample
Should Move
```

toward the clean signal.

---

The DDPM loop later converts:

```text
Velocity Prediction
```

into:

```text
pred_x0
```

(the estimated clean audio representation).

# Key Takeaways

- DiTDecoder is the core neural network inside VoiceDM.
- It operates in a 768-dimensional transformer space.
- Input audio representations are projected from 96 → 768 dimensions.
- A time embedding tells the model where it is in the diffusion process.
- Conditioning information comes from the encoder.
- 12 DiT blocks perform iterative reasoning over audio and conditioning.
- Output projection maps features back to the 96-dimensional audio feature space.
- The output is a velocity prediction used by the DDPM sampling loop.
- This is the primary "intelligence" responsible for audio generation.
